# B 站升级审计结论

本轮结论：`reframe`。

说人话：代码准备好了，但生产 B 还没切。正确顺序不是“一把升级到最新版”，而是先把当前引擎修到和 A 一样稳定，确认真实 Trillium Note 能用，再升级官方 26.810。

## 已经完成

- A 的关键稳定性修复已经按不可变生产 release 恢复进 Git，不再依赖“服务器上有、仓库里没有”的幽灵代码。
- B1（26.803 + A 稳定性修复）完整 CI 通过。
- B2（官方 Linux 26.810 + 版本限定薄适配）完整 CI、官方包签名、preload、Git、线程转换和 CLI 0.148 隔离协议探针通过。
- 发布脚本增加 A 健康守卫、五分钟资源守卫、B 后台任务守卫、release 锁、生产状态快照、代码/环境/状态回滚和资源上限。
- B 密钥已准备改为专用 group；不会再让 A 服务账号读取 B 密钥。
- 机器审计包通过校验：5 个关键问题内外部证据覆盖率、关键主张追溯率、搜索分支覆盖率和候选详情核验率均为 100%。

## 还不能说完成

- 当前身份没有 root，不能读取 B 生产 state、journal 或真实备份。
- 还没有证明生产 B 的快照能在隔离副本中由新旧 CLI 恢复。
- 还没有在登录后的真实浏览器里验收 B1/B2。
- 还不能确认 B 只保留 Trillium Note，也不能安全删除审计产生的 synthetic user。

## 固定发布顺序

1. root 只读盘点 B，确认真实用户、Trillium thread/project 和 synthetic user。
2. B 静止快照、SHA-256、SQLite integrity、隔离恢复、新旧 CLI 回读。
3. 只灰度 B1；真实登录完成加载、发送、语言、断线、后台和能力矩阵。
4. B1 连续稳定后重新快照。
5. 安装官方签名 26.810 pair，只灰度 B2；重复同一矩阵。
6. B2 达标后才清理测试数据、轮换 B 密钥并形成最终基线。

任一白屏、消息缺失/重复/刷新消失、语言无反应、后台任务中止、B 内存触顶、持续换页或 A 变慢，都停止晋级并回滚。

机器记录见 `audit.json`，真实命令见 `B-UPGRADE-RUNBOOK-2026-08-14.md`。
