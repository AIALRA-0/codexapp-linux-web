## 3. 真实页面与超大任务

测试使用 B 站保留的真实 Trillium Note 任务，原始任务约 613 MB。浏览器检查的目标不是只看到页面框架，而是必须看到该任务的最新正文

| 页面阶段                   | 实测耗时 |
| -------------------------- | -------: |
| 冷启动到文档结构加载完成   |  1.32 秒 |
| 冷启动到官方 renderer 挂载 |  2.40 秒 |
| 冷启动到页面外壳可见       |  6.84 秒 |
| 冷启动到最新正文出现       | 64.52 秒 |
| 热运行到页面外壳可见       |  4.96 秒 |
| 热运行到最新正文出现       | 10.53 秒 |
| 完整刷新后再次看到同一正文 |  8.77 秒 |

冷启动的主要等待发生在官方 app-server 解析超大任务：`thread/turns/list` 一次实测 43.75 秒，`thread/resume` 一次实测 49.38 秒

热运行时会复用官方 app-server 已返回且请求条件完全一致的结果。缓存只在当前服务进程内生效，不写入另一套历史数据库，也不会覆盖原始对话

## 5. 发送与离网页面

发送测试使用临时任务，不把测试内容留在正式任务列表

| 发送阶段            | 实测耗时 |
| ------------------- | -------: |
| 请求被服务端接受    |  15 毫秒 |
| 收到 `turn/started` |  61 毫秒 |
| 第一段可见模型输出  |  4.28 秒 |
| 回复完整结束        |  4.52 秒 |

后台测试启动一条 12 秒任务后立即关闭页面连接。服务端在第 5 秒仍报告任务运行，重新连接后收到原任务的完成事件，随后后台状态恢复为空闲

这证明关闭网页不会停止已经提交的任务。它不等于服务器断电后任务仍能继续；断电属于主机故障，需要依靠服务恢复和持久化数据

| Gmail                   | 通过             |
| Outlook                 | 通过             |
| AIALRA Shopping Browser | 通过             |
| Google Drive            | 等待用户重新连接 |

Google Drive 的返回原因是 `USER_NOT_LOGGED_IN`，不是宿主超时或 MCP 加载失败。连接应用的 OAuth 授权必须由用户账号确认，服务器不能替用户完成

旧版生产验证脚本还把已经退役的 `aialra_google_email` 当作必需服务，因此会一直等待。新版验证脚本改为检查当前官方连接应用；旧服务只在明确设置 `VERIFY_LEGACY_GOOGLE_EMAIL=1` 时进入兼容测试
