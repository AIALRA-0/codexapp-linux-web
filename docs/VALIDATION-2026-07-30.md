## 本轮修复

ChatGPT 模式的项目列表会调用官方路径 `/backend-api/gizmos/snorlax/sidebar`

VPS 上的普通 Node.js 请求和 WARP 请求都收到 OpenAI Cloudflare 403 挑战，说明失败来自网络栈识别，不是项目数据、账号或 renderer 协议

官方客户端同主版本的 Chromium 150 网络栈可以在同一台 VPS、同一个 ChatGPT 登录态下返回 HTTP 200

生产路线因此改为一个长期复用的 Electron 43.2.0 网络进程：

- 只接受这个官方地址的 GET 请求
- 仍使用官方请求格式和官方 JSON 响应
- 不接管模型对话、文件下载、SSH 或其他 VPS 流量
- OpenAI 令牌只通过父子进程管道传入，不写磁盘或命令行
- 子进程不继承宿主服务的其他环境变量
- Chromium 用户命名空间沙箱保持开启
- Ubuntu 全局 AppArmor 限制保持开启，只放行固定、不可写的 Electron 可执行文件

真实登录态结果：

| 路径                           | 结果                            |
| ------------------------------ | ------------------------------- |
| Node.js 直连                   | HTTP 403，Cloudflare 挑战       |
| Electron 单次直连              | HTTP 200，有效 JSON             |
| Electron 长驻进程首次请求      | HTTP 200，本轮约 1.36 秒        |
| Electron 长驻进程复用请求      | HTTP 200，本轮约 1.04 秒        |
| 生产 renderer 完整宿主路由请求 | HTTP 200，有效 JSON，约 0.89 秒 |

WARP 已从 CodexApp 配置和服务依赖中移除并停用

## 真实大对话封测

从 Mac 选择最大的一条真实旧任务，通过加密 SSH 临时复制到服务器隔离目录

测试前后完成以下保护：

- 本地和服务器副本 SHA-256 一致
- 不复制 OpenAI 登录凭据
- 不把任务并入生产用户目录
- 不输出任务编号或消息内容
- 测试结束后删除临时副本

样本大小为 442,034,684 字节

| 操作                     | 服务器内部耗时 | 峰值内存 |
| ------------------------ | -------------: | -------: |
| 启动官方 app-server      |         14.9 s |   541 MB |
| 列出最近任务             |          24 ms |    90 MB |
| 读取任务元数据           |          15 ms |    91 MB |
| 恢复最近 10 条消息摘要   |         19.5 s |  1.12 GB |
| 读取最近 10 条消息摘要   |         15.4 s |   895 MB |
| 读取前一页 10 条消息摘要 |         15.5 s |   887 MB |
| 完整读取全部消息         |         16.1 s |  1.10 GB |

结论：

- 任务可以完整恢复和读取，没有丢内容或超时
- 侧栏目录和元数据读取很快
- 点击极端大任务后的等待来自官方 app-server 解析 442 MB JSONL
- 公网延迟不是这 15–20 秒的主要来源
- 不新增私有历史数据库或自研对话格式
- 旧超大任务继续采用打包备份、按需恢复，不批量放入日常在线目录

大对话封测脚本现在会记录失败阶段，并只保留脱敏后的最后 20 条官方错误，避免今后只得到没有原因的“退出 1”
