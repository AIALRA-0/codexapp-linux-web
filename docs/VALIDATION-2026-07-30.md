## 本轮修复

ChatGPT 模式的项目列表会调用官方路径 `/backend-api/gizmos/snorlax/sidebar`

VPS 直连该路径收到 OpenAI Cloudflare 403 挑战，普通用量接口只返回正常的未登录响应，因此问题位于机房出口信誉，不是项目列表界面或宿主协议

本轮加入可选的本地出口：

- 只接受 `127.0.0.1`、`localhost` 或 IPv6 回环地址
- 不允许在代理网址中保存用户名或密码
- 只代理已确认受影响的官方项目列表请求
- 不代理模型对话、文件下载、SSH 或其他 VPS 流量
- 仍调用官方网址、官方请求格式和官方响应格式

这个能力已部署但默认关闭

启用前仍需服务器运营者接受代理厂商条款并验证出口，因此本轮没有代替用户完成该法律确认

## 尚未通过的两项

### GitHub 拉取请求

服务器已安装 GitHub CLI，但当前网页用户自己的隔离目录还没有 GitHub OAuth 授权

影响是拉取请求页面会显示需要登录，其他 Git、分支、差异和工作树功能不受影响

修复需要用户确认一次 GitHub 设备授权，因为它会为该服务器用户新增长期 OAuth 权限

### ChatGPT 项目列表的在线刷新

宿主已经具备最小范围的本地代理路线，但代理客户端尚未注册和启用

启用需要运营者接受 Cloudflare WARP 条款

完成后必须再验证：

1. 本地代理只监听回环地址
2. 官方项目列表路径不再收到 Cloudflare 挑战
3. 普通模型对话仍走原出口
4. SSH、站点和其他服务路由不变
5. 代理断开时宿主明确失败，不回退到自建数据
