## 超大真实任务

从本机选取一条 471,581,345 字节的真实旧任务，通过加密连接复制到服务器隔离目录。测试不复制登录凭据，不并入生产历史，不输出任务编号或消息内容。

最新官方界面检测到这条任务仍使用 `legacy` 历史模式，因此会按官方顺序执行恢复并读取最近 5 轮：

| 操作                      | 服务器内部耗时 |
| ------------------------- | -------------: |
| app-server 启动           |         589 ms |
| `thread/list`             |          16 ms |
| 任务元数据                |          23 ms |
| 官方恢复和最近 5 轮读取   |      31,599 ms |
| 返回数据                  | 6,369,870 字节 |
| app-server 进程树峰值内存 |     约 1.23 GB |

结论很明确：侧栏和元数据很快，点击这条极端旧任务后的约 32 秒来自官方 app-server 解析旧式大 JSONL，不是网页桥接和公网往返。官方当前没有提供 Codex 旧任务到新分页格式的安全转换接口；所谓外部导入接口只处理其他代理的会话。

项目不会为掩盖这个上游边界再造一套历史数据库。日常任务保留在线，极端旧任务打包备份并按需恢复。

## 发布与回滚

新版发布会同时切换三项：宿主版本、经过核验的官方包版本、期望的官方版本和构建号。任一项切换失败或健康检查失败，三项会一起回到上一版本，避免宿主和官方包错配。

候选版本、官方包、用户状态、密钥和旧版回滚目录继续分开保存。用户任务不存放在应用发布目录中，升级和回滚都不会转换对话格式。

最终安装器会排除本机 `.official` 缓存、版本库、运行状态、密钥和生成报告。生产发布目录约 282 MB；清理中间候选后只保留当前版本和一个已验证回滚版本。
