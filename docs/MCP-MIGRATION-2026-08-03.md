# MCP 迁移与重新连接说明

这份记录只说明能力状态，不保存账号、令牌、邮箱地址或 OAuth 回调信息。

## 1. 已经可以直接使用

| 能力                     | 服务器状态 | 验证方式                                                        |
| ------------------------ | ---------- | --------------------------------------------------------------- |
| OpenAI 官方文档          | 可用       | 完成官方文档搜索和正文读取                                      |
| GitHub                   | 可用       | 完成当前账号资料读取                                            |
| Gmail 官方连接器         | 可用       | 账号所有者重新授权后，完成真实账号资料读取                      |
| Outlook 云连接器         | 可用       | 完成当前账号资料读取                                            |
| AIALRA Google 多账号 MCP | 部分可用   | USC 账号有效；个人账号的旧授权被 Google 撤销，等待重新登录      |
| AIALRA Shopping Browser  | 可用       | Linux 虚拟显示下完成真实 Chrome 双客户端测试                    |
| 自定义 Microsoft MCP     | 已退役     | 原 RPI Microsoft 365 账号已经失效，服务端移除该连接且不阻塞上线 |

## 2. 需要用户重新授权

下面几项不能靠复制文件恢复。原因是本机源连接本身已经失效、断开，或从未完成过登录；服务器没有把一个有效连接迁坏。

| 能力                    | 当前情况                           | 用户需要做什么                           |
| ----------------------- | ---------------------------------- | ---------------------------------------- |
| Google Drive 官方连接器 | 本机已经断开                       | 在插件或连接器页面重新授权一次           |
| AIALRA Google 个人账号  | 刷新凭据已经被 Google 撤销         | 通过服务器回跳页重新登录个人 Google 账号 |
| Google Calendar         | 插件已安装，没有可迁移的活动 OAuth | 首次使用时完成授权                       |
| Slack                   | 插件已安装，没有可迁移的活动 OAuth | 首次使用时完成授权                       |

Google Drive 的官方连接和 AIALRA Google 多账号 MCP 相互独立。重新授权个人账号不会修改
仍然有效的 USC 账号，也不会恢复已经退役的 RPI Microsoft 365 连接。

## 3. 不能 1:1 搬到 Linux 的能力

Computer Use 连接的是 Mac 本机桌面和应用窗口。Linux 服务器没有同一套 macOS 图形界面，因此不能把它伪装成“已经迁移”。网页操作由官方 Browser 能力和服务器上的独立 Chrome 环境承担；需要操作 Mac 原生应用时，仍应在 Mac 客户端执行。

## 4. 验收规则

连接器只有在服务器完成一次真实只读调用后才记为“可用”。只发现配置文件、只列出工具名或只完成插件安装，都不能算功能正常。

OAuth 项只有用户完成重新授权并返回真实账号数据后，才能从“需要重新授权”改为“可用”。
