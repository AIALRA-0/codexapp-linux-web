# 2026-08-03 发布复验

## 1. 结论

本轮修复了三个会直接影响真实使用的问题：新任务可能启动失败、官方界面读取附件时反复报错，以及公网连接约每 60 秒中断一次

生产版本继续使用锁定并校验过的官方 renderer 和官方 Codex app-server，没有重写界面、对话协议或历史索引

修复后，真实账号页面连续在线超过 190 秒，跨过旧故障的三个 60 秒周期。期间新任务成功启动，没有再次出现连接中断、文件读取失败或动态工具命名空间错误

## 2. 根因与处理

| 现象                               | 根因                                                           | 处理方式                                                                 | 是否改变官方协议 |
| ---------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------ | ---------------- |
| 新任务一直加载或启动失败           | 宿主没有返回官方界面用于判断动态工具能力的结果，界面退回旧格式 | 实现官方桌面宿主已有的能力查询，让官方界面按原生规则发送带命名空间的工具 | 否               |
| 页面反复读取失败                   | 网页宿主缺少官方桌面的文本、元数据和二进制文件读取通道         | 按官方返回结构补齐三个文件通道，并限制路径、软链接和文件大小             | 否               |
| 点击、发送和切换一段时间后整体卡住 | 公网 WebSocket 空闲连接约每 60 秒被中间网络回收                | 服务端每 25 秒发送标准 WebSocket 心跳，浏览器按协议自动回应              | 否               |

三项修复都落在桌面宿主兼容层，没有修改官方 renderer 请求，也没有建立第二套业务协议

## 4. 真实账号观察

生产服务切换后，已经打开的真实账号页面自动重新建立连接

- 新的官方界面会话建立成功
- 真实 `thread/start` 请求在约 1.35 秒内完成，返回成功
- 观察超过 190 秒后仍未出现旧的无状态断线
- 同一时段没有出现文件二进制读取错误
- 同一时段没有出现动态工具缺少命名空间错误

这段观察证明本轮三个生产故障已经消失，但不等于把每个高风险按钮都在真实账号上重新执行了一次
