# 2026-08-03 发布复验

## 1. 结论

本轮修复了四个会直接影响真实使用的问题：新任务可能启动失败、官方界面读取附件时反复报错、侧边栏无法确认工作区路径，以及公网连接约每 60 秒中断一次

生产版本继续使用锁定并校验过的官方 renderer 和官方 Codex app-server，没有重写界面、对话协议或历史索引

生产版本 `20260803.1558-desktop-paths` 上线后，真实账号页面自动恢复连接。新任务成功启动，没有再次出现路径能力缺失、文件读取失败或动态工具命名空间错误

同一长连接修复的前一候选版本延长观察到约 8 分钟 19 秒时，公网连接出现一次没有关闭原因的异常断开。浏览器约 4.08 秒后自动发起恢复连接，随后官方在线请求继续成功。它没有造成任务丢失或服务重启，但说明公网链路仍可能产生短暂重连等待，不能写成“永不断线”

## 4. 真实账号观察

- 同一长连接修复在线观察超过 190 秒后，没有出现旧的 60 秒周期断线

- 同一时段没有出现侧边栏路径能力缺失
- 同一时段没有出现动态工具缺少命名空间错误

继续观察时记录到一次公网瞬时断开和自动恢复。服务全程保持运行，恢复后页面请求继续成功；这次等待属于公网与认证握手链路，不是对话读取或服务器进程重新启动

这段观察证明本轮四个生产故障已经消失，但不等于把每个高风险按钮都在真实账号上重新执行了一次

## 5. 剩余延迟来自哪里

生产记录显示，普通任务启动约 0.85 秒；官方插件列表通常需要约 1.8 至 3.7 秒，MCP 连接状态列表约需 5.9 秒。后两项慢在官方 app-server 枚举插件和连接状态，不是读取服务器里的历史对话

官方界面会同时发出参数不同的插件查询，也会发出少量完全相同的并行查询。宿主完整转交这些请求，以保证安装、卸载和授权后的状态与官方客户端一致。当前没有增加私有缓存或擅自合并请求，因为这会引入短时间内显示旧状态的风险

公网仍会增加登录握手和跨境访问时间。后续性能验收会分别记录浏览器到服务器、宿主处理、官方 app-server 和 OpenAI 上游四段耗时，避免把所有等待都归因于网络
